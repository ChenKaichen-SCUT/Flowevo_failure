# 环境、评分及信息边界

固定环境为 ScienceWorld 1.3.0、Python 3.10.12、OpenJDK 11.0.33。JAR SHA-256 为 `e77b0fee7d68abe3ca5b12e57d86e2bfe7603f20c5200da0b0f085939faeb465`，来自固定 ScienceWorld 提交自带工件，没有混用 1.2.x JAR。环境指纹和依赖锁随仓库提供。

官方 API 枚举出 30 个任务类型，TRAIN 3592、DEV 1796、TEST 1819 个 variation。原始 split 不合并重划；按稳定 SHA 排序选择。未使用的 TEST 清单保存在仓库外。任务名称用于加载，数字任务索引不作为跨版本契约。

每次加载明确 `simplificationStr=""`、`generateGoldPath=False`。不启用 easy，不读取 Gold、目标内部进度、世界对象树或不可见属性。模型只有 JSON 动作接口，没有 Python 执行、文件、网络或私有评估工具。公共视图使用字段白名单，单测验证 Gold 旧别名、Java/server、对象树及隐藏进度入口不能通过求解 facade 访问。

主成功标准预先固定为宿主读取的原生 `getCompleted()` 为真，且最终官方 score 恰为 100。Python wrapper 的 done 还会因 `moves > envStepLimit` 或负分而为真，因此 done 不是成功。分别保存原生完成、wrapper 终止、宿主 100 决策终止、最终分和最高分；主指标不用最高分替代最终分。数值 score/reward、完成标志及隐藏子目标不进入求解、规则生成或修订请求。

接口设置是 **official valid-action-assisted**：各组得到相同完整合法动作列表，未按答案或任务相关性过滤。合法动作可能无益，也可能在真实语义层失败；既不作为正确动作标签，也不用于自动替换模型输出。原始响应、解析动作、执行动作分别记录。空输出、无效 JSON、截断输出、非法动作、数字歧义选择都有独立测试。格式失败最多一次接口修复，响应到达后先记用量再做解析。

`reset()` 自带一次 `look around`，但并非每个命令都会增加环境 moves；环境移动数与宿主决策数分开。审计脚本最初错误地用“最终 moves 减命令数”推导初始 moves，产生 -2；已改为 reset 后直接读取并重跑，旧审计原件保留。这是审计元数据修复，不改变任何实验动作或评分。

同一冻结 TRAIN 前缀在两个串行实例和 1、2、4、8 进程池中重放，公开观察哈希一致。额外的自主成功轨迹重放同样一致。此证据仅覆盖被测前缀；每个局部分叉还要再次逐步核对自身来源前缀，不能把一次 smoke 当作所有任务的全局确定性证明。

校准机为 4 核、约 30 GiB 内存，cgroup 祖先未设额外 CPU/内存硬上限。短环境实例结束时 RSS 约 0.3 GiB，这不是连续测得的进程峰值。8 路模型短请求约 1.07 秒完成。训练采用 8 个独立 JVM 环境、最初全局 8 路异步模型信号量；正式运行前 8/16/8 阶梯校准显示 16 路短请求吞吐约为 8 路的 1.70 倍，无错误，故主实验使用 8 环境、全局 16 API 上限和共享连接池。模型访问只到官方 DeepSeek。JVM 与协调器监听本机地址，未开启调试端口。每批更换进程，批内多个作业复用同一 worker 的 JVM；5 秒资源采样见最终 `audit_summary.json`，采样不能保证捕捉瞬时峰值。

所有调用阶段共用 100 美元事务预算：发送前按 UTF-8 字节上界、消息开销和最大输出预留峰值无缓存费用；结算按供应商 usage，估算一律采用峰值价，UNKNOWN 保留预留且不自动重发。估算与供应商实际账单分开，未声称二者完全相同。
